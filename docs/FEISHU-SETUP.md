# 飞书 + ZCode 绑定配置指南

把飞书私聊接入 ZCode 机器人运行时。全程约 10 分钟。
以下每一条「坑」都是实际踩过的，逐条对照能省你一小时。

## 前置

- ZCode 桌面版已安装并登录（机器人运行时跑在本机）
- 飞书账号，且有权限创建自建应用（个人/小团队组织即可）

## 一、创建飞书应用（两条路线）

### 路线 A（推荐）：ZCode 扫码自动创建

ZCode → 设置 → **移动端远程控制** → Bot Channels → **新建机器人** → **飞书（中国）** → 用飞书 App 扫码。
ZCode 会自动创建应用并保存凭据，跳到本文「三、绑定工作区」。

### 路线 B：手动创建

[open.feishu.cn](https://open.feishu.cn) → 开发者后台 → 创建企业自建应用 → 记下 **App ID / App Secret** → 在 ZCode 机器人配置里填入。

### 应用配置检查清单（手动创建必查，扫码创建建议复核）

| 配置项 | 位置 | 必须值 |
|---|---|---|
| 机器人能力 | 应用能力 → 机器人 | 已启用 |
| 事件订阅 | 开发配置 → 事件与回调 | 含 **`im.message.receive_v1`（接收消息）** |
| 订阅方式 | 同页 | **长连接**（无需公网域名；配好后点「验证」应显示已连通） |
| 权限 | 开发配置 → 权限管理 | 接收消息相关权限（加事件时通常自动带出） |

## 二、发布版本（⚠️ 最大的坑）

应用配置改完**必须创建版本并发布**才生效。

> **坑 1：可用范围默认「指定成员」且名单可能是空的。**
> 空名单 = 机器人对全组织（包括你自己）不可见——搜不到、聊不了、事件照发但没人能触发。
> 创建版本时把 **可用范围改为「全体成员」**，再发布。
>
> 坑 2：改可用范围为全员通常会触发**组织管理员审核**；管理员在飞书管理后台批准后生效（小组织一般几分钟）。

验收标准：版本列表里最新版本状态 = **已发布**，版本详情里可用范围包含你。

## 三、绑定工作区

1. ZCode → 移动端远程控制 → Bot Channels → 选中你的飞书机器人
2. 面板上有 **绑定命令**（形如 `/bind XXXXXX`，30 秒刷新一次）
3. 在飞书里打开这个机器人的**私聊**，发送该绑定命令
4. 面板状态变为已绑定； thereafter 每条私聊消息都会在本工作区创建会话

> 坑 3：绑定命令有时效，复制后尽快发送；过期点「刷新绑定码」。
>
> 坑 4：飞书里可能同时存在多个同名机器人（你建过的智能体、其他框架的 bot）。认准**本次创建/绑定的那一个**；旧的不用了建议在开放平台停用，避免发错对话。

## 四、装上风险检测 Skill 并启用流水线

1. 按 README「风险检测 Skill」一节安装 `dbs-content-risk-check`
2. 把仓库根目录 [PIPELINE.agents.md](../PIPELINE.agents.md) 的内容复制进你工作区的 `AGENTS.md`（没有就新建）
3. 在飞书私聊发一篇稿子测试；机器人应依次回报：检测结果 → 改动清单 → 发布凭证

## 五、排障速查

| 现象 | 检查顺序 |
|---|---|
| 机器人搜不到 | 版本是否已发布 → 可用范围是否包含你 → 飞书客户端重启 |
| 消息发出但机器人不理 | 开放平台「运营与监控 → 事件日志」查 `im.message.receive_v1`：<br>无记录 = 消息发给了别的同名 bot 或事件未订阅；<br>有记录 SUCCESS 但本机无反应 = ZCode 侧运行时问题，重启 ZCode |
| 事件日志全空但配置都对 | 确认你聊的是**这个应用**的机器人（同名实体很多） |
| 长连接「验证」不通过 | ZCode 未运行或网络不通；重启 ZCode 后重试 |

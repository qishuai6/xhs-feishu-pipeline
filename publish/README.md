### ⚠️ 重要：dry-run 测试也会自动产生草稿（会攒垃圾）

小红书的编辑器**会自己周期性存草稿**（内容变更后约 30~60 秒落盘），**跟你点不点「暂存离开」没关系**。实测：草稿箱里 9 条图文草稿，其中 8 条是 dry-run / 调试会话留下的，只有 1 条是真点了「暂存离开」。

所以：

- 跑 `--dry-run` 做测试，**也会在草稿箱留下草稿**（一次会话最多 1 条，短会话可能来不及存）；
- 反复测试会攒重复草稿，标题看起来一样、保存时间不同；
- **脚本不会删除任何草稿**（删除是破坏性操作，不放进自动化）；
- 清理办法（手动，30 秒）：创作服务平台 → 左侧「草稿箱」→ 切到「图文笔记」tab → 每条右侧点「删除」；
- 草稿箱有上限：图文笔记最多 100 篇，超出后平台会自动删最后一篇——所以别拿它当测试仓库存东西。

## 二、日常怎么发（三种模式，自己选一种）

| 模式 | 命令 | 结果 |
|---|---|---|
| **定时发布（推荐）** | `--schedule "2026-11-05 19:31"` | 填好内容 → 开定时 → 到点 19:31 自动发 |
| **存草稿（默认安全）** | 不加任何发布参数 | 只存草稿，不点发布 |
| 立即发布（慎用） | `--publish` | 马上发出去，没有撤回 |

### 模式 A：定时发布（到点自动发）

```bash
cd /Users/qishuai/Documents/deepseek-harness/default-workspace/xhs-auto/publish

python3 publish.py \
  --meta "../notes/002-50岁还在跳槽/out" \
  --body body.txt \
  --title "她50岁还在跳槽，我反而被打醒了" \
  --tags "AI提效,人工智能,职场,内容创作,个人IP,复利思维,长期主义" \
  --schedule "2026-11-05 19:31"
```

脚本会：填内容 → 打开「定时发布」开关 → 把时间设成 `2026-11-05 19:31` → **回读校验确实是 19:31**（同时打开日历面板二次确认）→ 点【定时发布】（**没有二次确认弹窗，直接提交**）→ 去「笔记管理」确认记录并截图：记录会先出现在 **「审核中」**，状态标「定时发布 2026-11-05 19:31」。

- 只写 `--schedule "19:31"` 也行（= 今天 19:31）。
- **时间必须是未来**：已经过了 / 太近（<2 分钟）脚本直接报错退出，不会自己猜时间。
- 如果平台不接受这个时间（比如超出可选范围），会发生「回读值对不上」→ 脚本报错退出，不硬点。
- 发出前想改/取消：创作服务平台 → 笔记管理 → **定时发布** tab → 取消。
- 第一次用建议先加 `--dry-run --headed`：一路设到 19:31 并校验，**但不点发布**。

### 模式 B：存草稿（现在仍然保留）

假设长文已经渲染成了图片，放在 `xhs-auto/out/demo-magazine/`（`page-01.png`、`page-02.png`… 文件名顺序就是发布顺序）。

```bash
python3 publish.py \
  --images ../out/demo-magazine \
  --title "普通人最该做的是把消费换成资产" \
  --body ../out/demo-magazine/body.txt \
  --tags "复利,长期主义,普通人副业"
```

跑完会弹出浏览器自动操作一遍，最后**存进草稿箱**。去小红书创作平台左侧「内容管理 → 草稿箱」看一眼，确认没问题自己点发布。

存完草稿后终端会明确打印这一行（这是你判断「它没乱点」的直接依据）：

```
✓ 已存入草稿箱。请到 creator.xiaohongshu.com → 笔记管理 → 草稿箱 打开检查，确认无误后由你本人点击【发布】。本脚本未点击任何发布按钮。
```

> 小提示：小红书界面上的草稿按钮文案叫「**暂存离开**」，不是「存草稿」；脚本点的就是它（这个按钮藏在 closed shadow DOM 里，普通方式点不到，脚本用 CDP 定位 + 真实鼠标点击）。

### 想看它每一步在干什么：加 `--headed`

```bash
python3 publish.py --meta ../out/demo-magazine --body "..." --schedule "19:31" --headed
```

### 空跑（任何模式都能先试）

```bash
python3 publish.py --meta ../out/demo-magazine --body "..." --dry-run
# 定时发布空跑：
python3 publish.py --meta ../out/demo-magazine --body "..." --schedule "19:31" --dry-run
```

`--dry-run` 会一路把图片上传、标题正文话题全填好（定时模式还会把时间设好并回读校验），**停在最后一步，一个提交按钮都不点**，然后打印：

- 已填内容清单（几张图、标题、正文字数、话题、定时时间回读值）
- 本来要点的按钮和它的定位方式
- 当前页面截图路径
- 点击审计（每个点击的按钮文案 + 是否允许提交）

确认它找按钮找得对、内容填得对，再跑正式模式。

### 每次运行都会留一份可回溯报告

不管成功失败，`logs/run-report-<时间>.json` 都会写一份，记录：跑了哪几步、每步耗时、每步用了哪个选择器（命中/未命中）、点了哪些按钮（含 `allow_submit` 标记）、有没有重试、失败截图路径。

想看内容也可以加 `--report`，终端会额外把 JSON 打印出来。**怀疑账号有异常时，就查这份报告**——它是唯一能证明脚本到底干了什么的证据。

### 封面：当前不支持，不要用 `--cover-index`

封面设置**未实现（not implemented）**：还没在已登录的发布页上实测到「封面/设为封面」的真实 DOM，按项目规矩不猜、不盲点。传了 `--cover-index` 脚本会明确提示并忽略。
默认第 1 张图就是小红书封面，要改就在草稿箱里手动设。

### 直接用渲染产出的 meta.json（更省事）

如果图片是 `xhs-auto/out/<风格>/` 里渲染出来的，那个目录里有个 `meta.json`（含 title/images），可以直接：

```bash
python3 publish.py --meta ../out/demo-magazine --body "正文写在这里"
```

- `--meta` 可以是 `meta.json` 文件路径，也可以直接给目录（自动找里面的 `meta.json`）
- meta 里认识的字段：`title` / `body` / `tags` / `images`
- **命令行参数优先于 meta**，比如 `--title` 会覆盖 meta 里的标题
- 注意 meta 里的 `title` 是给图片排版用的双行大标题，经常超过 20 字；脚本会压成一行并截到 20 字并打警告，真正发小红书建议还是手动给一个短 `--title`

### 真发布（危险操作）

只有明确要发的时候才加 `--publish`：

```bash
python3 publish.py --images ../out/demo-magazine --title "..." --body "..." --publish
```

⚠️ 加了 `--publish` 就是**立刻真的发到线上账号**，没有撤回。
日常建议用 `--schedule`（定时发布）：到点前还能在「笔记管理 → 定时发布」取消，有安全窗口。

## 三、参数说明

| 参数 | 必填 | 说明 |
|---|---|---|
| `--images` | 是* | 三种写法都行：①一个目录（自动按文件名排序取 png/jpg）②`"a.png,b.png"` 逗号分隔 ③通配符 `"../out/demo-*/*.png"`。**顺序就是发布顺序，第 1 张默认是封面** |
| `--title` | 是* | 标题，**最多 20 个汉字**，超了会被小红书截断 |
| `--body` | 否 | 正文文本；也可以给一个 `.txt` 文件路径，脚本自动读 |
| `--tags` | 否 | 话题，逗号分隔，不用写 `#`，例如 `"复利,长期主义"` |
| `--meta` | 否 | 可选：render 产出的 `meta.json`（或它所在目录），自动读 title/images/tags。给了它，`--images`/`--title` 就可以不写 |
| `--draft` | 否 | 存草稿（**默认就是它**，写不写一样） |
| `--schedule` | 否 | **定时发布**：`"YYYY-MM-DD HH:MM"`（也支持 `"HH:MM"`=今天）。设好后点【定时发布】，平台到点自动发 |
| `--publish` | 否 | 立即发布（立刻发出去，没撤回）。不写就永远是草稿 |
| `--dry-run` | 否 | 空跑：全填好、停在最后一步、一个提交按钮都不点，打印清单+审计 |
| `--report` | 否 | 结束时把运行报告 JSON 打印到终端（报告本身每次都会写进 logs/） |
| `--headed` | 否 | 显示浏览器窗口（默认后台无头跑，看不到操作） |
| `--cover-index` | 否 | **未实现**（not implemented），传了会提示并忽略；封面默认第 1 张 |
| `--dump` | 否 | 只打开发布页把 DOM 存下来，不填内容（改版排查用） |

> \* 用 `--meta` 时 `--images` / `--title` 可以不写。

图片限制：最多 18 张（小红书图文上限）。

## 四、风险与边界

**一句话**：脚本能模拟一部分操作特征（随机延迟、真 Chrome），但**模拟不掉行为规律**——所以日常别高频、别多号，用它省手工而不是放大量。

- 脚本默认只做「上传 + 填写 + 存草稿」，**不点发布**；只有你显式加 `--schedule`（定时发布）或 `--publish`（立即发布）才会点。
- `--schedule` 是最推荐的发法：设好 19:31 后由平台到点自动发，**发出前你可以在「笔记管理 → 定时发布」取消**，有安全窗口。
- 单账号、单浏览器、串行、不并发、不批量。
- 不碰点赞/评论/关注/私信，不刷数据，不搬运内容。
- 不改 UA、不挂代理、不用云服务器，走你本机自己的网络。
- 完整的行为承诺清单见 [`SAFETY.md`](SAFETY.md)。

## 五、失败了怎么办

每次运行都会在 `logs/` 里留东西：截图（`step-*.png` / `dump-*.png`）、页面 DOM（`dump-*.html`）、可见文本（`dump-*.txt`）。
失败时终端会告诉你**卡在第几步**，把对应文件发出来就能定位。

常见情况：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 报 `未登录` / 被跳到登录页 | 登录态过期了（小红书会清） | `python3 login.py --qr` 重扫一次 |
| 报「找不到上传控件」/「切不到上传图文 tab」/「找不到暂存离开按钮」 | 小红书改版（发布页默认停在「上传视频」tab、tab 有隐藏副本、底部按钮在 closed shadow DOM 里，这三处最容易变） | 先跑 `explore.py` 重新勘察，把新结论补进 `SELECTORS.md`（见下） |
| 上传卡住、缩略图数量不对 | 图片太大/网络慢；或格式不是 png/jpg | 图片压到 2MB 以内，用 png/jpg；重跑一次 |
| 标题被吞/截断 | 超过 20 字 | 自己把 `--title` 改短 |
| 话题没有变成蓝色链接 | 该话题没有「完全同名」的平台话题，脚本会保留纯文本并打印警告 | 不影响发布；可以事后在草稿箱里手动改话题 |
| 页面弹出「已关联活动」提示 | 你选的某个话题恰好是平台活动话题，平台自动关联 | 平台行为，脚本不控制；活动关联可在发布页手动取消 |
| 报「定时发布暂不可用 / 需要认证」 | 该账号暂时没有定时发布权限 | 脚本会立刻停止不硬写；先手动在网页上试一次定时发布 |
| 报「平台没有接受这个时间」 | 时间已过 / 太近 / 超出平台可选范围 | 换一个未来时间重跑；脚本不会自己改时间 |
| 定时发布后「笔记管理」没找到记录 | 记录先出现在「审核中」而不是「定时发布」（刚提交要审核）；也可能列表未刷新 | 去「笔记管理 → 审核中」找，状态会写「定时发布 HH:MM」；**确认前不要重复发布** |
| 浏览器启动报 `ProcessSingleton`/profile 被锁 | 有另一个进程在用 `.profile` | 关掉之前 run 的 Chrome/脚本（脚本已能自动清理已死进程的残留锁） |
| 提示「chromium 找不到」 | 本机 playwright 自带浏览器版本不匹配（已知） | 不用管，脚本强制用系统 Chrome `channel="chrome"` |

# 安全说明：这个脚本会做什么、不会做什么

> 当前路线：**路线 2 · 定时发布**（原路线 1「半自动存草稿」保留）。
> 脚本负责「打开创作平台 → 传图 → 填标题/正文/话题 → 打开定时发布 → 设成当天 19:31」，
> 然后点【定时发布】。**平台到点自动发出；发出前你可以在「笔记管理 → 定时发布」取消。**
> 不加 `--schedule` 时，脚本默认仍然只存草稿、绝不点发布。

---

## 一、这个脚本会做什么（逐条）

1. **只操作小红书创作平台发布页**：打开 `creator.xiaohongshu.com/publish/publish`，在这一个页面里完成上传和填写。
2. **只上传你本人指定的图片**：就是命令行 `--images` 给你的那些文件，按你给的顺序上传，不多传、不改图。
3. **只填你本人给的标题、正文、话题**：内容 100% 来自你的输入或你的 `meta.json`，脚本不生成、不改写、不添加任何内容。
4. **默认存草稿**：不加 `--schedule` / `--publish` 时，脚本只点界面上的「暂存离开」（=存草稿），**从不点【发布】**。
   - `--schedule` 模式：脚本会打开定时发布开关、设好时间、回读校验，然后点按钮文案为「定时发布」的按钮。
   - `--publish` 模式：立即发布（不推荐日常用，没有撤回）。
5. **每一步都走安全闸门**：所有点击都经过同一道检查，草稿模式下碰到文案是「发布 / 立即发布 / 确认发布」的按钮会立刻拦截并停止。
6. **操作之间带随机延迟**：每次操作间隔 0.3~1.2 秒随机，接近真人节奏，不做毫秒级连点。
7. **全程串行**：一次只跑一个浏览器、一个账号、一篇笔记，跑完就关。
8. **失败就停下**：任何一步找不到元素就停止，截图 + dump 页面存进 `logs/`，不会瞎点下一个按钮。
9. **留运行报告**：每次运行写一份 `logs/run-report-<时间>.json`，记录跑了哪些步骤、耗时、点了什么、有没有失败。这是你事后回溯的唯一证据。
10. **登录态只存在本机**：登录信息保存在 `xhs-auto/publish/.profile/`（你自己电脑上的浏览器配置目录），已加入 `.gitignore`。
11. **只在你自己的电脑上跑**：浏览器就是你本机的 Chrome，IP 就是你自己的网络，没有远程执行。
12. **可以空跑验证**：`--dry-run` 会把内容全填好、停在最后一步，打印「已填清单 + 将要点的按钮 + 点击审计」，一个提交按钮都不点。

## 二、这个脚本不会做什么（逐条）

1. **只在你显式要求时才点发布**：默认存草稿；只有 `--schedule`（定时发布）或 `--publish`（立即发布）才会点，而且必须你亲手加参数。
2. **不会跳过你的确认**：`--schedule` 点的是【定时发布】，不是立刻发出去——到点前你有窗口去「笔记管理 → 定时发布」取消。
3. **不会发多篇**。一次运行只处理一篇笔记。
4. **不会并发**。没有多线程、没有多浏览器并行、没有多账号轮换。
5. **不会点赞、评论、关注、私信、转发**。脚本只碰发布页，不碰任何互动功能。
6. **不会改 User-Agent，不会挂代理/IP 池，不会用云服务器**。用的是你本机、你日常的 Chrome、你家/办公室的 IP。
7. **不会改浏览器的指纹伪装**。脚本只关闭了 Chrome 自带的「自动化提示条」，不伪造任何硬件特征。
8. **不会读取或导出你的 cookie / 密码 / 手机号**。登录靠你自己扫码；`.profile/` 是登录态本身，不解析、不打印、不上传。
9. **不会批量注册、不会养号、不会刷数据、不会搬运别人的内容**。
10. **不会修改你的图片、不会加水印、不会压缩替换**，上传的就是你给的原文件。
11. **不会在后台偷偷跑**。脚本在终端前台运行，跑完就退出；关掉终端就没了。

> 已知的平台自动行为（不是脚本行为，但你该知道）：
> 你选的话题如果恰好是小红书的「平台活动话题」，页面会自动提示「已关联活动」。这是平台按话题标签自动挂的，脚本不控制；不想要这个关联，在发布页手动去掉即可。

## 三、你的账号风险到底来自哪里

平台风控看的不是「有没有用浏览器自动化」这一件事，而是**行为规律**：

| 风险信号 | 脚本的现状 |
|---|---|
| 发布频率异常（一天几十篇） | 脚本不做限制，**要你自己控制**：一天 1~3 篇、别连发 |
| 同 IP 多账号 | 脚本单账号、单浏览器，**只要你别多号同时跑**就没这个问题 |
| 内容高度重复/搬运 | **你写原创内容**，这条天然规避 |
| 机械操作特征（毫秒级连点、固定路径） | 脚本加了 0.3~1.2s 随机延迟，**降低**这类特征 |
| 互动异常（刷赞刷评） | 脚本完全不碰互动功能 |

**一句实话**：脚本能模拟一部分操作特征，但**模拟不掉行为规律**。
所以正确的用法是「用它省掉手工复制粘贴的力气」，不是「用它把发布量放大十倍」。
一天一两篇、真人节奏、坚持原创——在这三条前提下，这个脚本不给你增加新的风险面。

## 四、两种路线的边界

- **你本人做内容的判断**：标题、正文、话题、图片顺序，都是你定的；脚本只负责搬运。
- **你本人做发布的决定**：草稿存好后，脚本打印
  `✓ 已存入草稿箱。请到 creator.xiaohongshu.com → 笔记管理 → 草稿箱 打开检查，确认无误后由你本人点击【发布】。本脚本未点击任何发布按钮。`
- **平台侧最后确认**：即使自动化出了问题，最坏结果也只是「草稿没存好」，不会出现「错误内容被发出去」。

## 五、你可以怎么验证它真的没点发布

1. 跑 `--dry-run`：内容全部填好、停在最后一步、**一个提交按钮都不点**，终端会打印「已填内容清单 + 本来要点的按钮 + 点击审计」。
2. 看 `logs/run-report-*.json` 里的 `clicks` 数组：草稿模式下每一项的 `allow_submit` 都应该是 `false`，且没有一条文案是「发布」。
3. 跑完去草稿箱看：内容在，笔记没发出去。
4. 跑之前先 `login.py --check`：登录态不对就停，不会带着登录墙乱点。

## 六、什么时候你会想停下来

- 出现验证码/滑块/异常提示：手动处理完再跑，别让脚本硬闯。
- 一天已经发过几篇：等一等，别为了「测试链路」反复真发。
- 你换了电脑或清了浏览器数据：重新扫码一次就好。
- 平台改版导致步骤失败：看 `logs/` 里的 dump 修正选择器（方法见 `README.md` / `SELECTORS.md`），别硬改代码去猜按钮。
